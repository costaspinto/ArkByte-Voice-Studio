HISTORY CONTROLS

- Use the trash icon beside one history row to permanently remove that history record and its generated audio file.
- Use Clear history to delete all generation history and generated audio files. A confirmation is shown before the request.
- Neither operation deletes voice profiles, original reference recordings, saved projects, model weights, caches, or unrelated files.
- Bulk clear is rejected while a generation is queued or running, to avoid racing output creation.
- The backend resolves each output path and requires it to remain inside the ArkByte outputs directory. Invalid/outside paths are rejected. The bulk operation validates every path before it starts deleting files.
- This uses ordinary filesystem deletion. It is not forensic secure erase; backups, snapshots and exported copies may remain.

RESPONSIBLE-USE SAFEGUARDS

- Existing profile-creation and enrolment consent checks remain required. The acknowledgement wording now explicitly rejects unauthorised cloning and misuse.
- Every generation request must also send rights_ack=true. The API rejects requests without this explicit acknowledgement and checks that the selected profile has a stored consent acknowledgement.
- The UI prohibits agreement to use generated speech for impersonation, deception, fraud, harassment, non-consensual intimate content or identity/biometric-verification bypass, and asks for synthetic-speech disclosure where listeners could be misled.
- The full policy is in docs/SAFE-USE-POLICY.md.
- These are user-attestation and deterrence controls, not proof of identity, legal advice or a guarantee that misuse is impossible. A person controlling the local machine may modify local software. The operator remains responsible for consent, applicable law and platform rules.
